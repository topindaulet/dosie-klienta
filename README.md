# Досье клиента — прототип

Реализация раздела 10 из [PRD2.md](PRD2.md): кликабельный фронтенд-прототип для передачи разработчикам как референс по UX/вёрстке.

## Запуск

```
node server.js
```

Открыть http://localhost:4173

## Что реализовано (соответствие пп. 4.1–4.4 ТЗ)

- Форма данных о клиенте, все поля необязательны (4.1).
- Переключатель типа клиента (юр./физ./оба) с динамической перестройкой чек-листа (4.2), полный перечень пунктов — из Приложения A.
- По каждому пункту — ссылка на источник и ссылка на поиск с подставленным именем/ИИН/БИН клиента (4.2).
- Ручной ввод найденного текста и даты проверки по каждому пункту (4.3).
- Экспорт карточки в файл, совместимый с Word (.doc, открывается в MS Word), и копирование текстовой сводки в буфер обмена (4.4).
- Локальное сохранение и список карточек — демонстрация модели «мои карточки» (4.5, упрощённо).

## Чего здесь нет (продуктовая версия требует решений из раздела 8 ТЗ)

Это статический фронтенд без сервера и БД: данные хранятся только в `localStorage` браузера конкретного сотрудника.
Для боевого использования нужно:

- Backend + БД с шифрованием данных в хранении (раздел 5).
- SSO/AD-авторизация вместо поля «Сотрудник» (раздел 5).
- Ролевая модель доступа сотрудник/руководитель/админ (раздел 6).
- Полный аудит-лог действий (раздел 5).
- Политика хранения/удаления записей после даты встречи (раздел 5, вопрос 2).
- Согласование с комплаенс по персональным данным (вопрос 1) и по доступу с мобильных устройств вне офиса (вопрос 3).
- Выбор внутренней инфраструктуры размещения (вопрос 4).

Ссылки на источники ведут на официальные сайты и на Google-поиск с подставленным именем/БИН/ИИН — согласно разделу 7,
автоматический парсинг/скрапинг госреестров сознательно не реализован.
